시작 시 반드시:
1) 환경 변수 BLOGGER_CLIENT_SECRET 내용을 client_secret.json 파일로 저장
2) 환경 변수 BLOGGER_TOKEN 내용을 token.json 파일로 저장
3) python3 -m pip로 아래 패키지 설치
   - google-auth-oauthlib
   - google-auth-httplib2
   - google-api-python-client
   - requests
   - Pillow
4) 아래 “필수 실행 순서”를 한 글자도 빼지 말고 끝까지 수행

════════════════════════════════════════
목표
════════════════════════════════════════
가장 이슈가 큰 정보성 키워드만 골라, 독자가 “무슨 일인지 / 영향 / 방법 / 해결”을
바로 이해하게 글을 작성·발행한다. 글은 짧지 않게, 실무에서 바로 써먹을 수 있을
정도로 구체적으로 쓴다.

이번 자동화에서 자주 빠지는 아래 두 가지를 절대 생략하지 말 것:
A) Blogger labels(태그) 약 20개
B) 다른 포스트와 같은 품질의 AI 시네마틱 썸네일
   (Pillow 막대그래프/도형 폴백으로 발행 금지)

════════════════════════════════════════
필수 실행 순서 (매 실행 동일)
════════════════════════════════════════
[STEP 1] 자격 증명/의존성 준비 (위 1~3)

[STEP 2] 1차 실행
  python3 publish_trend.py

[STEP 3] AI 썸네일 필수 처리 (exit code 2 이면 무조건 수행)
  - publish_trend.py 가 AI plate 부재로 exit 2 로 끝나면, 로그에서 다음을 읽는다:
    - REQUIRED_SLUG=...
    - REQUIRED_SAVE_PATH=generated_images/ai-thumb-{slug}.png
    - REQUIRED_IMAGE_PROMPT_BEGIN ~ END 사이 전체 프롬프트
  - 그 프롬프트로 GenerateImage 도구를 즉시 호출한다 (16:9).
  - 결과 이미지를 REQUIRED_SAVE_PATH 경로에 저장한다.
    예: generated_images/ai-thumb-google-earnings.png
  - 저장 후 반드시 다시 실행:
    python3 publish_trend.py

[STEP 4] 발행 성공 검증 (하나라도 실패면 미완료)
  - 발행/수정 URL이 로그에 있을 것
  - labels 개수가 15개 이상(목표 20개)일 것
  - 본문에 class="post-thumb" 이미지와 jsDelivr CDN URL이 있을 것
  - 썸네일이 추상 Pillow 도형/막대만인 상태가 아닐 것
  - quality ok 로그가 있을 것

중요:
- AI 썸네일 없이 글을 올리면 실패다. Pillow 폴백 발행 금지.
- 태그 3~4개만 달고 끝내면 실패다. 약 20개여야 한다.
- “나중에” 하지 말고, 같은 실행 안에서 STEP 2→3→4를 끝낸다.

════════════════════════════════════════
선정 규칙
════════════════════════════════════════
- 엔터테인먼트·연예·단순 인명·스포츠 경기 결과 제외
- 돈이 되거나 실생활에 영향 있는 이슈만 선정 (금융·법률·건강·생활안전·투자 등)
- 실제 뉴스 보도로 사실관계가 뒷받침되는 것만 선정
- 여러 무관한 기사가 같은 단어만 공유하는 일반 명사성 키워드(응집도 낮은 키워드) 제외
- 가장 이슈가 되는 것만 작성
- 실행당 기본 1개 (BLOGGER_MAX_POSTS_PER_RUN 기본값 1)
- cron 4시간마다(하루 6회) → 하루 최대 약 6개 수준 유지
- 애매하면 억지로 쓰지 말고 줄이거나 0개로 종료

════════════════════════════════════════
글 작성 규칙
════════════════════════════════════════
- 글 1개 = 키워드/이슈 1개
- 제목만 읽어도 이슈와 유용성이 보이게 작성
- 본문은 정보성을 충분히 확보 (짧은 요약체 금지, 체감 분량 약 3배)
- 검색 의도 맞추기:
  - 실적발표/어닝스: 대출·세금 프레임 금지.
    “발표 일정 / 실적 숫자·컨센서스 대비 / 관전 포인트 / 확인·대응” 중심
  - 금융·제도: 일정·적용 대상·내 계약·계좌 확인 중심
  - 생활안전·건강·법률: 영향 대상과 즉시 확인할 행동 중심
- 본문 필수 구조:
  1) 이슈가 무엇인가 (보도 근거 + 맥락)
  2) 무엇이 영향받는가 (대상 + 경로)
  3) 관련해서 확인할 방법 (공식 발표 → 내 계약/계좌/지역 → 후속 보도)
  4) 해결·대응 방법 (체크리스트 + 피해야 할 실수)
  5) 관련 소식 (실제 기사 링크·출처)
- 가능하면 Q&A, 한눈에 정리 포함
- 추상 문구(“관심이 많습니다”) 반복 금지
- 본문에 ‘자동 포스팅’ 표현 금지
- 티커/종목코드 사람 읽기 쉬운 표기
  예: tsla → 테슬라(TSLA), 005930 → 삼성전자(005930)

════════════════════════════════════════
태그(Blogger labels) — 필수, 약 20개
════════════════════════════════════════
- build_labels()가 만들도록 그대로 사용 (직접 3개만 넣지 말 것)
- 구성:
  1) 카테고리 1개 (금융/투자/건강/생활안전/법률)
  2) 핵심 키워드/토큰
  3) 뉴스 헤드라인 토큰
  4) 주제/카테고리 확장 태그
- 목표 개수: 20개 (최소 15개 미만이면 발행 중단)
- 금지: 문장형 태그, 연예/가십 태그, 중복 태그
- insert / 빈 포스트 patch / draft update 모든 경로에 labels 포함
- 발행 후 post.labels 개수를 로그로 확인하고 quality ok 를 볼 것
- 예시(실적발표):
  ["투자", "구글 실적발표", "구글", "실적발표", "어닝스", "분기실적",
   "컨센서스", "가이던스", "EPS", "매출", "영업이익", "빅테크",
   "클라우드", "AI", "알파벳", "IR", "공시", "실적", "발표", "2분기"]

════════════════════════════════════════
썸네일 — 필수, 다른 포스트와 같은 AI 품질
════════════════════════════════════════
목표 스타일:
- 시네마틱/포토리얼 뉴스 썸네일 (삼성전자·근저당 썸네일 수준)
- 배경 장면 안에 한글 헤드라인이 자연스럽게 들어감
- 우측 하단 @욘두두 워터마크
- Pillow 추상 원/막대그래프만 있는 이미지는 실패

파이프라인 강제 규칙:
1) generated_images/ai-thumb-{slug}.png (또는 .jpg) 가 있어야만 발행 진행
2) 없으면 publish_trend.py 가 exit 2 + REQUIRED_IMAGE_PROMPT 출력
3) 에이전트는 GenerateImage로 생성 → 저장 → publish_trend.py 재실행
4) 최종 파일은 posts/images/thumb-{slug}.jpg 로 커밋/푸시
5) 본문 최상단에
   <p><img class="post-thumb" src="https://cdn.jsdelivr.net/gh/yeonjoo2025/blogger@{sha}/posts/images/thumb-{slug}.jpg" ...></p>
6) BLOGGER_ALLOW_PILLOW_THUMB 을 켜서 폴백으로 발행하지 말 것

GenerateImage 프롬프트 작성 시 추가 제약:
- 16:9
- 로고/브랜드 마크/실존 연예인 얼굴 금지
- 가짜 확정 실적 숫자(EPS·매출 구체값)를 읽히게 넣지 말 것
- 하단 반투명 배너 오버레이 금지
- 제목 템플릿의 “대출·세금” 같은 문구 때문에 장면이 바뀌면 안 됨
  (키워드 기준으로 장면 결정)

════════════════════════════════════════
발행/운영
════════════════════════════════════════
기본 명령: python3 publish_trend.py

발행 우선순위:
1) 사람이 만들어 둔 빈 LIVE 포스트가 있으면 posts.patch 로
   제목·본문·태그·썸네일을 채워 발행
2) 사람이 만들어 둔 DRAFT가 있으면 update 후 publish
3) 셸이 없을 때만 posts.insert 신규 생성

빈 포스트 판별:
- 본문이 비었거나 거의 비어 있음
- 또는 제목이 신규/빈 포스트/Untitled/새 게시물 등

빈 포스트가 있으면 insert 한도가 막혀 있어도 수정(patch/update) 경로로 작성한다.
단, 태그 20개 + AI 썸네일 조건은 수정 경로에서도 동일하게 필수.

하루 신규 발행 한도:
- posts.insert 일일 한도 이슈 가능 (신생 블로그는 더 낮을 수 있음)
- 한도 소진/insert 403·429 시:
  - 빈 포스트/드래프트 셸이 있으면 그 셸을 수정해 작성
  - 셸이 없으면 신규 생성하지 않고 기존 일반 글도 수정하지 않음
  - 바로 종료 후 다음 주기 재시도
- 상태 파일: .blogger_quota_state.json

보안/Git:
- 시크릿/토큰 값을 로그·커밋·채팅에 출력하지 말 것
- client_secret.json, token.json, .blogger_quota_state.json,
  pending_posts/, generated_images/ 는 Git에 올리지 말 것
- 커밋되는 이미지는 posts/images/thumb-*.jpg 만

환경변수(선택):
- BLOGGER_MAX_POSTS_PER_RUN (기본 1)
- BLOGGER_MAX_NEW_POSTS_PER_DAY (기본 50)
- BLOGGER_REQUIRE_AI_THUMB (기본 1, 끄지 말 것)
- BLOGGER_ALLOW_PILLOW_THUMB (기본 미설정, 켜지 말 것)
